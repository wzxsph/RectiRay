# 复现 RectiRay

[English](../../docs/reproducibility.md) · [简体中文](reproducibility.zh-CN.md)

RectiRay 从合成照片学习几何，再用预测几何摆正原照片。基本顺序是：**准备源片 → 合成拍摄场景 → 训练 → 固定开发集检查 → 目视审阅**。想了解为什么调整训练配方，可以先看[数据研究历程](research-journey.zh-CN.md)。

请按手头的资料选择路径：

| 现有资料 | 可以做什么 |
| --- | --- |
| 只有代码 | 运行合成测试，不需要 X 光片或权重。 |
| 获授权的新图片，已按训练／开发划分目录 | 按第 3 节准备和检查新数据包。这是在准备**新的实验**，不是重放仓库报告的结果。 |
| 原研究数据包、初始化资产和检查点 | 按第 4–6 节核对并运行现有实验。 |

当前训练入口绑定原来的 **4,114 个训练文件、478 个开发文件、28 个隔离文件**及其精确清单。新清单即使数量相同，也不代表兼容。这里尚未提供可直接适配任意新数据集的微调入口。

## 1. 安装并检查环境

使用 Linux、Python 3.11 或 3.12，以及 PyTorch 后端的 Keras。下面的命令使用 Python 3.12 和 `uv`，请先安装这两个工具。训练需要支持 BF16 的 CUDA 显卡。已测试的训练配置为 24 GiB RTX 4090 D、16 核 CPU 配额；请核实当前机器的实际资源。

```bash
git clone https://github.com/wzxsph/RectiRay.git
cd RectiRay
uv venv --python 3.12
uv pip install --python .venv/bin/python -e '.[dev]'
export KERAS_BACKEND=torch
export RECTIRAY_ROOT="$PWD"
PY="$RECTIRAY_ROOT/.venv/bin/python"
"$PY" -c 'import torch, keras; print("torch", torch.__version__, "keras", keras.__version__, "CUDA", torch.cuda.is_available(), "BF16", torch.cuda.is_bf16_supported() if torch.cuda.is_available() else False)'
CUDA_VISIBLE_DEVICES='' "$PY" -m pytest -q
```

**通过条件：**合成测试通过。训练时 CUDA 和 BF16 检查均须为 true。安装项目依赖并不会精确还原旧 CUDA 环境；`requirements.lock` 记录的是一次环境快照，不负责安装显卡驱动。

## 2. 将数据与代码分开存放

使用仓库已忽略的 `.local/` 目录。输入与生成的数据包都留在本地；不要上传其中的影像、清单、报告或权重。

```text
.local/
  incoming/                  # new-data path only
    sources/{train,dev,quarantine}/
    backgrounds/{train,dev}/ # actual photographs; not generated viewer screens
    provenance.json          # optional source and license notes
  prepared/new-bundle/       # generated by prepare_data.py
  assets/                    # existing-experiment path: authorized original assets
    bundle/
      data/manifest.json
      data/split.json
      data/backgrounds-manifest.json
      ...                    # image files at the exact manifest-relative paths
      weights/b11.weights.h5
      weights/g0.pt
      weights/g0.json
    backgrounds/             # root for background manifest-relative paths
    start/step-2000.pt
    start/frozen-protocol.json
  runs/                      # checkpoints, state, training logs
  cache/                     # rebuildable synthesized inputs
  reviews/                   # local metrics and comparison pages
```

本公开源码仓库不分发模型权重。三个历史分阶段备份包含已训练检查点和元数据，保存在独立受控私有归档中；[权重与源码对应表](../../docs/checkpoint-source-map.md)记录当前保存入口、摘要和源码绑定。这些分阶段备份**不包含**原始数据包、两份初始化资产或保存的起点协议。所需资产应通过获授权的途径另行取得；只下载备份不足以复现。数据来源与许可见[第三方来源](../../THIRD_PARTY.md)。

## 3. 准备新数据，保留已有划分

将已经分好组的图片放入上述 incoming 目录。`quarantine/` 可以为空；训练和开发目录都必须包含源片和真实照片背景。有可靠患者分组时，同一患者的资料应保持在同一组；工具既不推断患者身份，也不宣称划分已满足患者独立。

```bash
"$PY" tools/prepare_data.py \
  --sources "$RECTIRAY_ROOT/.local/incoming/sources" \
  --backgrounds "$RECTIRAY_ROOT/.local/incoming/backgrounds" \
  --output "$RECTIRAY_ROOT/.local/prepared/new-bundle"
"$PY" tools/check_assets.py --mode data \
  --bundle "$RECTIRAY_ROOT/.local/prepared/new-bundle" \
  --backgrounds "$RECTIRAY_ROOT/.local/prepared/new-bundle/backgrounds"
```

**产物：**`data/` 下的三份加载器可读取清单、源片与背景的逐字节副本，以及本地准备报告。准备阶段不缩放图片、不做增强。稳定排序与哈希便于对照重复准备的结果，源文件保持不变。

**通过条件：**所有图片可解码、哈希一致，训练和开发之间没有文件相同或解码像素相同的图片。隔离区中的重复项会保留并报告。工具拒绝已有输出目录、符号链接和越界路径；准备失败时不会留下看似完整的数据包。检查器会打印 JSON 汇总；加上 `--report "$RECTIRAY_ROOT/.local/reviews/data-check.json"` 可保存为新的本地报告。

可加 `--provenance "$RECTIRAY_ROOT/.local/incoming/provenance.json"` 记录来源与许可说明，格式见 `--help`。它记录输入信息，不代替许可或隐私审核；未提供来源时会明确记为未指定。查看器界面、近色及混色环境由场景生成器制作，新数据包不需要另备 1,100 张界面图片。历史数据包可原样保留这些清单项。

**这条路径到此结束。**新数据包用于另行定义的实验，不要交给绑定旧数据的 step-2000 训练入口。

## 4. 检查原实验资产

后续步骤使用**原始数据包和原样的清单文件**，不能换成第 3 节重新生成的数据包。下面的命令使用当前源码开始新运行；如果要重放已经保存的历史运行，须在恢复或评估检查**之前**完成[隔离源码准备](#进阶历史源码与数值模式)。从仓库根目录一次设置好这些路径：

```bash
export BUNDLE="$RECTIRAY_ROOT/.local/assets/bundle"
export BACKGROUNDS="$RECTIRAY_ROOT/.local/assets/backgrounds"
export PARENT="$RECTIRAY_ROOT/.local/assets/start/step-2000.pt"
export PARENT_PROTOCOL="$RECTIRAY_ROOT/.local/assets/start/frozen-protocol.json"
export CACHE="$RECTIRAY_ROOT/.local/cache/rectiray"
export RUN="$RECTIRAY_ROOT/.local/runs/rectiray-01"
export TRAINING_SOURCE="$RECTIRAY_ROOT"
export PYTHONPATH="$TRAINING_SOURCE/src"
PARENT_SHA=016cfc5b3fb97699eb38b6ce8850c7d4802797602d8fba04f233959744120535
"$PY" tools/check_assets.py --mode start \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" \
  --checkpoint "$PARENT" --checkpoint-sha256 "$PARENT_SHA" \
  --parent-protocol "$PARENT_PROTOCOL" --source-root "$TRAINING_SOURCE"
```

**通过条件：**数据、初始化、G0 配套文件、起点检查点和固定开发集指纹相互一致。检查器读取三个源片分组和每条背景记录，包括训练加载器不会消费的资产，不会改写清单。

2000 步检查点同时提供已学习的模型参数和 Adam 状态。新运行采用修订后的配方与新的确定性样本序列。这是在新数据上继续学习，既不是随机初始化训练，也不是旧样本流的逐位续训。当前取图器与历史训练时不同；要精确复现历史检查点，请按文末说明准备隔离源码。

## 5. 预检、训练与恢复

第 4 节检查通过后，先创建一个**独立的 CPU 零步运行**，核对加载并写入初始状态，不进行优化器更新。`--skip-training` 会跳过加载器对图片文件的校验，因此零步成功**不能代替**完整资产检查：

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m ptrn_pipeline.step2000_runner \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" --cache "$CACHE" \
  --parent "$PARENT" --parent-protocol "$PARENT_PROTOCOL" \
  --source-root "$TRAINING_SOURCE" \
  --output "$RECTIRAY_ROOT/.local/runs/preflight-01" --steps 3000 --skip-training
```

**产物：**`branch-step-0.pt`、绑定与来源文件，以及 `sample-sequence.npy/json`。这个目录须与正式训练的新目录分开。

分配好 GPU 并准备开始训练时，运行：

```bash
"$PY" -m ptrn_pipeline.step2000_runner \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" --cache "$CACHE" \
  --parent "$PARENT" --parent-protocol "$PARENT_PROTOCOL" \
  --source-root "$TRAINING_SOURCE" \
  --output "$RUN" --steps 3000 --gc-interval 4
```

**执行内容：**最多新增 3,000 次更新；224 输入、实际与有效 batch 均为 64、Adam 优化器，冻结 DenseNet201 和 BatchNorm。CPU 工作进程提前准备场景；GPU 交替执行训练更新与诊断预测，CPU 指标计算继续进行。每 250 次更新保存一次检查点。步数表示更新次数，不是不同源片数或 epoch 数。

**查看进度：**`training.jsonl` 记录更新与损失，`runner-status.json` 记录各阶段进度。另查 `completion.json` 中训练与评估各自是否完成。损失降低或运行完成，本身不能证明实拍取图效果合格。

运行器保存的检查点不可覆盖，但不会自动生成哈希目录。在生成检查点的机器上记录 SHA-256，并在复制运行目录时一起保留：

```bash
sha256sum "$RUN"/branch-step-*.pt > "$RUN/checkpoint-SHA256SUMS.txt"
```

恢复中断的训练时，保留**整个原运行目录**。将 `RESUME` 设置为其中最新、完整的已保存检查点，将 `RESUME_SHA` 设置为既有哈希记录中的对应值。不能用尚未保存的打印步数恢复，不能在留有后期检查点的目录中回退到更早节点，也不能为了掩盖不匹配而重新生成预期哈希。Release 资产则使用随包提供的校验元数据。然后执行：

```bash
"$PY" tools/check_assets.py --mode resume \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" \
  --checkpoint "$RESUME" --checkpoint-sha256 "$RESUME_SHA" \
  --parent-protocol "$PARENT_PROTOCOL" --run "$RUN" \
  --source-root "$TRAINING_SOURCE" --steps 3000
"$PY" -m ptrn_pipeline.step2000_runner \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" --cache "$CACHE" \
  --parent "$PARENT" --parent-protocol "$PARENT_PROTOCOL" \
  --source-root "$TRAINING_SOURCE" \
  --output "$RUN" --steps 3000 --gc-interval 4 --resume "$RESUME"
```

**通过条件：**检查点、优化器、随机数状态、已消费样本游标、样本序列、源码和资产一致。单独把 Release 的 `.pt` 复制进空目录，不构成可恢复的训练运行。不要更改目标步数，也不要编辑绑定 JSON 来掩盖不匹配。

## 6. 评估并查看结果

从运行中选定检查点及其已记录 SHA，设置为 `CHECKPOINT` 和 `CHECKPOINT_SHA`，并选用一个尚未使用的评估目录：

```bash
export EVAL="$RECTIRAY_ROOT/.local/reviews/dev-check-01"
"$PY" tools/check_assets.py --mode evaluate \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" \
  --checkpoint "$CHECKPOINT" --checkpoint-sha256 "$CHECKPOINT_SHA" \
  --source-root "$TRAINING_SOURCE"
"$PY" -m ptrn_pipeline.evaluation prepare \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" --cache "$CACHE" \
  --output "$RECTIRAY_ROOT/.local/reviews/dev-prepare-01" --workers 4
"$PY" -m ptrn_pipeline.evaluation predict \
  --bundle "$BUNDLE" --backgrounds "$BACKGROUNDS" --cache "$CACHE" \
  --checkpoint "$CHECKPOINT" --output "$EVAL" --batch 1 --workers 4 --graph
```

`prepare` 缓存固定场景；`predict` 执行 GPU 推理并启动 CPU 指标工作进程。该命令返回**不代表**指标计算已经结束。请等待 `metrics-complete.json` 和 `evaluation.json`，期间可查看 `metrics-progress.json`。出现 `inference-failed.json` 或 `metrics-failed.json`，都表示该次评估失败。

之后核对并汇总完整结果：

```bash
"$PY" tools/summarize_development.py --run rectiray="$EVAL" \
  --output "$RECTIRAY_ROOT/.local/reviews/development-summary.json"
```

**通过条件：**全部 **5,736** 个唯一固定开发视图齐全，检查点与协议绑定一致。可重复传入 `--run label=directory`，比较多次完整评估。要一起看新增裁损、背景和几何，将 4,589 个拍摄视图与原片保留视图区分开。开发集已经参与选模，这些结果不代表独立实拍准确率。

要在本地做目视对照，将 `AUTHORIZED_PHOTOS` 指向获授权的照片目录，并给检查点指定显示名称。如果之前使用过历史源码树，先明确切回当前取图器：

```bash
export PYTHONPATH="$RECTIRAY_ROOT/src"
"$PY" tools/compare_real_photos.py --bundle "$BUNDLE" \
  --photos "$AUTHORIZED_PHOTOS" --checkpoint rectiray="$CHECKPOINT" \
  --output "$RECTIRAY_ROOT/.local/reviews/real-01" --allow-renderer-update
```

这个 CUDA 工具会写出 `index.html`、本地审计和**照片副本**。审阅片区保留、残留背景、摆正效果和不确定边界。研究中的 47 张照片已用于开发，没有可靠的成对边界真值，必须留在本地。取图器参数只允许已经明确审计过的渲染改动，不是通用的源码检查绕过开关。同时比较早期 pipeline 检查点时，还需添加限定范围的 `--allow-parent-source-updates`，详见[源码对应表](../../docs/checkpoint-source-map.md)。

## 各脚本负责什么

| 入口 | 输入 → 结果 |
| --- | --- |
| `tools/prepare_data.py` | 已分组图片目录 → 新本地数据包和来源报告；不做增强或训练。 |
| `tools/check_assets.py` | 数据包及可选检查点／运行目录 → CPU 完整性与兼容性报告；不修补数据。 |
| `ptrn_pipeline.step2000_runner` | 原始资产和起点检查点 → 训练及检查点；`--skip-training` 只写零步状态。 |
| `ptrn_pipeline.evaluation prepare` / `predict` | 固定开发数据／检查点 → 缓存、预测与异步指标。 |
| `tools/summarize_development.py` | 完整评估目录 → 经过核对的聚合对照。 |
| `tools/compare_real_photos.py` | 获授权照片与检查点 → 本地目视审阅；它本身不构成独立基准测试。 |

## 进阶：历史源码与数值模式

当前源码保留了模型契约，但取图器包含后续增加的面积重采样。要严格评估或恢复历史检查点，先创建隔离源码树；不要覆盖正在使用的 `src` 目录：

```bash
REPLAY="$RECTIRAY_ROOT/.local/replay-source"
git worktree add --detach "$REPLAY" HEAD
cp "$REPLAY/training-source-overlays/pipeline-parent/partial_geometry.py" \
  "$REPLAY/src/ptrn_hip/partial_geometry.py"
export TRAINING_SOURCE="$REPLAY"
export PYTHONPATH="$TRAINING_SOURCE/src"
```

对于更早的 pipeline 检查点，还需从同一历史文件目录复制 `partial_data.py` 和 `partial_synthesis.py`。以 `--source-root "$TRAINING_SOURCE"` 再次运行资产检查器；**所有记录的文件哈希都匹配**，才能称为历史重放。各阶段对应文件见[源码对应表](../../docs/checkpoint-source-map.md)。命令仍从主仓库根目录执行，以使用当前的检查工具。这一步恢复的是源码兼容性，不保证跨环境的长时间 GPU 训练逐位一致。

保留参考评估的 **batch 1 CUDA Graph／TF32** 模式。更大 batch 曾超出既定数值容差；`--strict-fp32` 是独立审计模式，不是等价替代。训练中的 eager 诊断也与参考评估不同。训练时的 `--eval-limit` 或评估时的 `--count` 只用于冒烟检查，不得称为完整结果。资源调度、Graph／固定页内存并发故障及 GPU 关机下载流程见 [AutoDL 实践](../../docs/autodl-training-practice.md)。
