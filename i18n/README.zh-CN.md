# PTRN Hip：从手机照片取出髋关节 X 光片

**语言：**[English](../README.md) · 简体中文

给一张手机拍摄的 X 光片照片，PTRN Hip 尝试找到片子、摆正透视，并从**原照片**中取出实际拍到的影像。

> **研究状态：**当前展示的分支 **+2250** 是根据已暴露合成开发集和先前查看过的实拍选出的候选。它尚未通过独立实拍或临床验证，也未替换应用模型。

*使用已审计的公开源片制作的固定合成示例。片子有一部分在照片之外；输出保留拍到的内容，不补造缺失的解剖影像。[来源与图像审计](../docs/figures/examples/zh-CN/CREDITS.md)。*

这个流程要做三件事：

1. **找到片子。**预测有序四角和完整参考平面的宽高比，即使角点落在照片之外。
2. **摆正拍到的部分。**从原照片采样一次，放到摆正的画布。没有拍到的像素仍标记为无效，不会被重建。
3. **保留可信原片。**有可靠来源的数字原片可以逐像素保留；模型不能仅凭图像看起来平整就推断其来源。

可以从这里开始：

- **看效果：**看下文[六个合成示例](#六个合成示例)，包括缺角、近色边缘和可信原片。
- **看实现：**从[代码地图](../docs/code-map.md)找到模块，再运行下文的[仅代码检查](#复现)。
- **复现实验：**拥有获授权的数据和权重时，按[训练与评估指南](../docs/reproducibility.md)核对资产并运行。源片和权重不随 Git 提供。

## 工作原理

![PTRN Hip 架构：224 输入、DenseNet201 四尺度特征、空间融合、四角和比例预测、辅助可见掩码，再从原照片一次取图。](../docs/figures/i18n/architecture.zh-CN.svg)

照片先等比例缩放、补边至 **224 × 224**，并按 ImageNet 通道统计量归一化。DenseNet201 的四级特征各投影为 64 通道并融合；四角按**左上、右上、右下、左下**排序，坐标采用补边输入的像素中心约定。另一个残差修正四边推得的对数宽高比。辅助可见掩码用于训练，**不负责二次裁剪或自动准入**。

取图器将预测参考平面与原照片相交，从原照片**只采样一次**，并返回实际拍到像素的有效掩码。边界不确定时，结果可能多留背景；模型不会填充照片外的 X 光内容。坐标、裁剪与取图器细节见[可见平面 V3](../docs/partial-v3.md)。

## 我们目前知道什么

在同一批 **4,589 个已暴露合成拍摄视图**上，分支 +2250 比分支 +2000 少切掉一些可见片区，同时多留了一些背景：

| 指标 | 分支 +2000 | 分支 +2250 |
| --- | ---: | ---: |
| 平均新增裁损：可见片区落在预测区域外 | 3.43% | **2.25%** |
| 平均残留背景：预测区域落在可见片区外 | **2.54%** | 3.54% |

![已暴露开发集上，分支 +2000 与 +2250 的新增裁损和残留背景取舍。](../docs/figures/i18n/tradeoff.zh-CN.svg)

这两项指标都依靠**合成真值**，使用相同的 4,589 个拍摄视图。固定开发全集有 5,736 个视图；表格排除了原片保留视图，以免稀释拍摄图的表现。数字来自已完成评估的聚合结果，经过四舍五入；**不是独立实拍准确率**。+2250 是在已暴露资料上选出的研究候选，不能只凭较低裁损断言取图问题已解决。

| 来源 | 本地清单中的文件数 | 在仓库示例中的使用 |
| --- | ---: | --- |
| [MTDDH](https://www.nature.com/articles/s41597-025-05146-x) | 1,849 | 原始版本的再分发条款尚未直接核实，不用于效果图。 |

| [Fraiwan DDH X-ray v2](https://data.mendeley.com/datasets/jf3pv98m9g/2) | 354 | 页面标注 CC BY 4.0；逐张审核像素及元数据后用于示例。 |
| **合计** | **4,620** | **训练 4,114 · 已暴露开发 478 · 隔离 28** |

训练合成不同占幅、透视、局部入镜和近色边缘的照片，也模拟相机或屏幕干扰。每个开发文件对应 12 个固定场景，共 **5,736 个视图**，保持旧的 `partial-v3` 场景配方。新的 `ptrn-step2000-unified-v1` 合成配方只用于训练；因此比较两个检查点时，考卷没有跟着改变。训练的本地背景池包含 4,400 张 COCO 2017 照片和 1,100 张程序生成界面图，**仓库不再分发背景池**。COCO 照片遵循各自的 Flickr 条款，详见[第三方来源](../THIRD_PARTY.md)。

![训练场景合成：源 X 光片、相机几何、缺损、拍摄外观和背景分别采样。](../docs/figures/i18n/synthesis.zh-CN.svg)

当前分支从已核验的正式流水线 **step 2000** 权重和 Adam 状态起训，并在新的确定性样本游标上最多进行 **3,000 个新增更新步**，每 250 步保存检查点。**+2250 指新增 2,250 步**，不是旧训练的绝对步数 2250，也不是旧样本流的逐位续训。设置为 224 输入、实际和有效 batch 均为 64、头部学习率 1 × 10⁻⁴、`stage=head` 下冻结 DenseNet201 编码器和 BatchNorm 统计量。损失综合四角、比例、可见掩码与几何有效性，并对漏掉可见片区给予高于多留背景的代价；照片外的虚拟四角不会被统一惩罚。每个检查点绑定配方、源码、资产、优化器、随机数状态与**已消费**样本游标。

## 可用性与限制

- **真实照片尚无独立成绩。**478 个开发源文件、5,736 个固定场景以及 47 张实拍都已在研究中被查看或使用；实拍没有可靠的成对边界真值，无法据此计算真实漏片率。47 张及其逐例网页只留本地，不进入 GitHub。新的、未参与开发的实拍与可靠参考仍是独立验收所必需的。
- **边界和缺损仍困难。**模糊或与背景同色的边缘、局部入镜都可能让结果残留背景或产生几何形变；方法只展平拍到的内容，不能重建缺失的解剖影像。
- **资产并非公开可用。**训练影像、背景和权重未随 Git 提供；研究检查点是私有备份，不是可部署模型。访问私有备份也不授予上游初始化、训练影像或微调权重的再分发权。数据集页面的许可标注不足以免除逐图隐私与下游用途审查。

当前目视审阅采用的取图器比训练时多一项经审计的重采样更新；这些可视化不能称为训练时渲染的逐像素重放。本文的论文式展示不表示髋片研究论文已发表，也不构成临床声明。

## 复现

**仅检查代码**不需要病例图或权重。使用 Python 3.11/3.12、PyTorch 和采用 PyTorch 后端的 Keras 3：

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python -e '.[dev]'
CUDA_VISIBLE_DEVICES='' KERAS_BACKEND=torch .venv/bin/python -m pytest -q
```

**训练和完整开发集验证**还需要单独获授权的本地源片、背景、初始化与父权重，以及已核 SHA 的清单；这些不在 Git 中。按[复现指南](../docs/reproducibility.md)运行并核对全部 5,736 个唯一视图、检查点绑定和评估完成标记。`--eval-limit` 仅用于诊断。这里不提供缺少公开权重却假称可立即执行的推理命令。
