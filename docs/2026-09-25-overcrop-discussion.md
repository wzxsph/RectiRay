# 5000 步为何在实拍上越裁越小

本稿仅作诊断与方案讨论，不授权启动训练、修改应用模型或替换数据。用户反馈是：两版权重都有过裁，1250 步通常还能保留较完整的可用区域，5000 步明显向内裁掉原本可见的影像。目标仍是保留照片里实际存在的完整 X 光影像，去掉外部背景并摆正；不是寻找骨骼后裁一个紧框。

**当前最有证据的解释是：5000 步在合成分布上进一步收紧了取图范围，但这种变化迁移到实拍时产生了明显的范围内缩。近满幅拍摄样本缺口、拍摄外观差距和训练目标的实际作用值得优先排查。还不能认定“训练太久”或“缺损图太多”就是唯一原因。**

## 1. 实际测到了什么

复用既有比较网页的全部预测，在原照片坐标中计算 `预测四边形 ∩ 照片边界` 的面积。没有重新推理、改门槛或扩大四点。

| 对照 | 47 张实拍 | 原网页 100 张合成图 |
| --- | ---: | ---: |
| 5000 比 1250 取图面积更小 | 47/47 | 67/100 |
| 面积缩小超过 10% | 42/47 | 4/100 |
| 5000/1250 面积比中位数 | 78.24% | 98.76% |
| 1250 范围中未被 5000 保留的面积比例，中位数 | 22.26% | 2.95% |

最后一行考虑位置偏移，所以与单纯的面积比不是同一个量。**1250 的预测不是正确答案；这些数字不能解释为“丢掉了 22% 的有效医学影像”。** 它们证明范围变化存在。真实损失量仍需人工确认有效影像边界，不能用更大的框自动冒充更正确。

按实拍面积中位数、以 1250 为 100% 比较：1250→100%，2500→83.61%，3000→94.22%，4500→84.12%，5000→78.24%。变化并非每个阶段单调收缩，因此不能简单拟合“多训练一步就多裁一点”的规律。5000 是这些已保存点中实拍范围最小的一个。

目视复核了两个收缩较明显的已有样例：5000 输出确实遗漏了 1250 中可见的部分影像，不只是网页显示比例变化。其中一例的 1250 输出同时保留较多界面／背景，说明较大的范围也有代价；这不是宣称 1250 对所有图都正确，亦不是全 47 张人工验收。

本地逐图计算保存在忽略目录 `.local/pipeline-v1/overcrop-discussion/paired-region-analysis.local.json`；原图与五组权重比较网页保存在 `.local/pipeline-v1/gallery-147/index.html`。这些产物含受控逐例资料，GitHub 上没有对应文件。全部匿名编号沿用旧网页。

## 2. 不是当前网页门禁把好框挡掉了

网页生成器使用相同的 `rectify_visible(photo, quad, ratio)`，直接展示候选结果，不经自动通过门禁。它采用预测四边形与照片的交集，从原图一次透视采样。辅助分割图不会再阈值裁一遍，也没有按训练步数增加裁边量。

因此，这次 **5000 的源坐标取图范围本身已变小，问题在进入最终取图之前就出现了**。比例预测会改变输出宽高和视觉拉伸，但在几何合法时，不会解释原坐标四边形交集为何少了约两成。放宽门禁只能让结果被输出，不能找回已经落在预测范围之外的内容。

证据入口：[候选取图](../src/ptrn_hip/partial_geometry.py)、[模型读出](../src/ptrn_hip/partial_model.py)。这排除了该网页使用旧自动门禁导致本轮现象的解释，不代表所有历史后处理都没有问题。

## 3. 为什么合成成绩变好，实拍却退步

重新汇总两份完整开发集结果；下表仅取其中 4589 张拍摄场景，避免原片保留样本稀释问题。

| 合成开发指标 | 1250 | 5000 |
| --- | ---: | ---: |
| 平均角点误差，占输入对角线 | 2.514% | 1.768% |
| 平均新增裁损 | 2.568% | 2.483% |
| 新增裁损中位数 | 1.562% | 1.733% |
| 平均多余背景 | 4.291% | 2.547% |

5000 去背景和角点误差改善明显；完整性改善很小，裁损中位数反而变差。4589 张中有 **2387 张**的新增裁损高于 1250。不能仅凭总 loss 或平均角点误差宣布取图更好。

两个检查点的数据、源码和损失绑定相同，均为 224 输入、有效 batch 64、`stage=head`。DenseNet 编码器被冻结，空间解码器、四角读出及辅助头在更新。不是 5000 自动换成了更强主干，也不是两者架构不同。1250 消费 80000 个视图，5000 消费 320000 个视图；步数不是原片张数，更不是 5000 个 epoch。

这些证据更符合“在当前合成分布上学得更熟，实拍上的预测偏差却扩大”。“模型把某类纹理或画面比例当成边界线索”是机制假设，需控制变量实验验证，暂不作为已证明的因果结论。

## 4. 优先排查的三类原因

### 4.1 近满幅的拍摄图存在明确缺口

当前 `partial_synthesis.sample` 只使用占幅档 0 和 1，对应 **30%–50%、50%–75%**。完整拍摄图在后裁剪之前不会走 75%–90% 档；100% 占幅主要由不加拍摄干扰的 `keep` 原片承担。后裁剪确实可能抬高最终占幅，所以不能说整个数据集完全没有超过 75% 的图。

现有 100 张审阅合成图中的 48 张完整拍摄图，没有一张超过 75% 占幅；超过 75% 的 4 张拍摄图全部来自缺损场景。这个小网页不代表训练分布的精确频数，但与生成代码的缺口一致。

这样模型常见到的是“干净原片→铺满照片”和“有拍摄外观的片子→四周有较多背景”。现实却可以是“照片几乎全是影像，边框仅剩一点，同时有摩尔纹、反光或屏幕纹理”。**将后者预测成训练中熟悉的较小框，是值得优先验证的解释。** 尚未为全部实拍标真实边界，不能声称已知道 47 张的真实占幅分布。

证据入口：[数据配方](../src/ptrn_hip/partial_data.py)、[实际调用档位](../src/ptrn_hip/partial_synthesis.py)、[占幅区间](../src/ptrn_hip/unified_synthesis.py)。

### 4.2 裁损有惩罚，但不等于完整性已经得到保证

检查点使用的实际损失是：

`坐标误差 + 3×漏掉的可见面积 + 多余背景 + 非法几何 + 掩码 BCE + 0.25×比例误差`

所以不能说代码在明确“奖励内缩”，也不能说完全没考虑漏片。正确问题是：这些项的尺度、梯度以及合成监督是否足以约束实拍的完整性。

坐标项按 1% 对角线归一化；完整性项则是软面积比，二者数值单位不同。系数 3 不能直接解释为整个训练过程都把完整性放在背景的三倍优先级。当前损失在合成样本上运算，真实边界误识别不会自动被纠正。

辅助掩码 BCE 的末 100 步平均值由约 0.678 降到 0.670，变化很小；且该掩码不直接决定取图四点。是否真的学到了清楚的外边界，需要另查 IoU、边界召回和角点／掩码一致性，不能凭这个 loss 数字断言分割成功或失败。

更合理的下一步是同时检查“漏掉多少可见区域”和“每条边向内偏了多少”，再做损失项梯度审计及单因素权重对照。若缺角的虚拟四点没有可靠可见证据，应降低不可辨识外推对已拍到区域的支配，而不是让模型把范围缩进画面来消除不确定性。

### 4.3 缺损强度和样本比例值得调整，不能只继续堆数量

目前拍摄图的配方是：完整 60%、轻缺损 30%、中缺损 10%。轻缺损目标为原参考平面面积的 2%–9%，中缺损为 12%–28%；另有 25% 的拍摄图先裁母片，保留面积下限为 70%。前裁与后裁可重叠。

这是“缺损拍摄占四成”，并非只有少量缺角例子。是否过多取决于真实使用频率，当前缺少这项统计。但为了针对用户描述的“稍缺一点，其余完整保留”，优先增加接近 0 的轻缺损、减少中重裁剪，比继续大量增加严重缺损更合理。

前裁母片本身不必然教坏模型：若裁后的图就是新的完整参考平面，标签应包住它的全部内容；后裁照片则应继续保留原平面的虚拟四点与实际可见区域。**训练见过缺角，不等于推理时被允许主动再切掉一个角。** 这两类标签若混淆才会直接违背目标；当前代码区分了它们，尚未发现标签被统一重置成内部小框的证据。

## 5. 关于“占幅从 100% 到 10%”的建议

这里将占幅定义为 **照片内可见底片面积／照片总面积**，不是边长比例，也不是缩放倍率。与缺损率分开记录：近景缺角图可能占幅很高，完整远景图可能占幅很低。

赞成扩大覆盖，但不建议每个占幅区间等量采样。对当前向内缩的问题，优先补的是 **75%–100% 的完整或轻缺损拍摄图**，10%–30% 只作少量远景补充。若均匀铺开小目标，会同时改变目标大小分布，无法确认改善或恶化来自哪里。

下面是待讨论的初始分布，**不是已生效配方**。继续保留全体样本 20% 的原片逐像素保留；剩下 80% 拍摄图按下表分配，并继续屏幕、胶片各半。

| 拍摄图最终占幅 | 拍摄图内比例 | 用途 |
| --- | ---: | --- |
| 大于 90%、小于 100% | 20% | 几乎贴边，但具有真实拍摄外观 |
| 大于 75%、不超过 90% | 30% | 补齐当前最直接缺口 |
| 大于 50%、不超过 75% | 35% | 维持常见近景 |
| 大于 30%、不超过 50% | 10% | 常见中景 |
| 10%–30% | 5% | 少量远景及复杂背景 |

这样拍摄图中 85% 仍超过 50% 占幅；10%–30% 是旧“至少 30%”条件的显式候选扩展，不会偷偷套进旧数据版本。100% 原片和“满画幅但带拍摄干扰”应分别有场景类型，不能都依赖 `keep` 旁路。

高占幅与大旋转／强透视未必同时可行：保持轻形变为主，对不兼容的组合按预先约定的条件采样并报告覆盖，不能靠拉伸底片或篡改占幅标签凑数。低占幅图要先做 224 输入可辨性审阅；例如理想正方形在正方形照片中占面积 10%，网络侧边长大约 71 像素，而不是 22 像素，但细边缘依然更难定位。不要把“有四点标签”当成“图上一定有足够证据”。

## 6. 缺边缺角以适度为主

建议首轮只改变后裁剪分布时，采用以下候选：

| 拍摄后缺损程度，按原参考平面面积 | 拍摄图内比例 |
| --- | ---: |
| 不缺损 | 80% |
| 轻微，缺 1%–3% | 12% |
| 轻度，缺大于 3%–8% | 6% |
| 中度，缺大于 8%–15% | 2% |

超过 15% 的严重缺损先保留在单独压力审阅组，不占首轮主体；这不意味着产品遇到它们应拒绝保留可用部分。覆盖单边、角部和相邻两边，尤其是“整条外边界已出画面，但剩余大片影像仍可用”的情况，不能只造四角都清楚的小缺口。

母片预裁剪另作变量：建议先考察拍摄图的 10%–15%，每次移除原母片面积不超过 5%–10%；首轮避免再叠加明显后裁剪。这样可以把“原文件本来就是局部影像”和“拍摄没有拍全”分开教清楚。上述数值仅是较保守起点，需要实拍频率和用户审样反馈校正，不是从本轮观察推导出的最优比例。

无论哪类缺损，目标都应是 **摆正照片中已存在的可用影像，尽量不新增裁损**。不能用完整参考平面的不可见部分逼网络补画内容，也不能把反光遮挡当成几何缺失。

## 7. 先做能辨认原因的对照

建议保留 1250 为必须比较的完整性参考与回退候选，不把它自动确定为新训练起点，也不因 5000 合成指标好就默认续训它。47 张已用于开发，任何后续选择都不能再称独立真实泛化验证。

1. **补实拍边界审阅。** 对 47 张记录必须保留的可见影像范围、明确背景和不确定区域；允许只给可确认的边／区域，不能强行造完整四点真值。用户指出的关键部位作为“不可新增裁损区域”，同时仍保留全片完整性要求。先完成五个已有检查点的逐图对照与方向性偏差统计。
2. **先隔离近满幅缺口。** 固定起点、外观与缺损分布，仅增加 75%–100% 拍摄场景。另设仅降低裁剪强度的组；不要第一轮把占幅、外观、缺损、损失和编码器一起改掉。
3. **单独验证外观影响。** 对同一几何用清晰／摩尔纹／反射配对，测预测范围是否因外观改变而内缩。新的 100 张外观审阅配方仍等待用户确认；没有必要先训练到 5000 才发现样例不真实。
4. **若仍内缩，再查目标和适应能力。** 先看坐标、完整性、背景及掩码项对共享层的梯度与边界偏差，再比较完整性约束；之后才独立比较解冻 conv5。当前冻结主干限制了适应能力，但这不等于已证明编码器容量不足。
5. **按取图质量选检查点。** 使用相同配对种子、更新预算、样本量和检查间隔，分别记录漏片、背景、几何及各占幅／缺损层结果。不能由 1250 与 5000 的一次差异直接定死最优步数。新相机、新场景的未暴露资料在方案冻结后验证。

不建议用固定比例扩大所有四点作为主要修复：当前既有整体内缩也有位置变化，统一放大可能保住一边却引入另一侧界面，并改变透视关系。可以把有限外扩作为离线反事实诊断，但不能只看“留得更多”就判胜；必须同时检查新增背景和变形。

## 8. 本轮交付与未解决项

已完成全部 47 张实拍和 100 张合成图的预测范围数值对照，重新汇总完整开发集的两检查点指标，核对两检查点绑定及相关源码，并目视检查两个明显收缩样例。未修改合成、损失、训练、阈值或权重，未操作云端。

现已确认实拍范围收缩和具体数据缺口；尚未测得 47 张的真实裁损率、真实占幅分布及各原因的贡献。下一轮的成功标准应是“原本可见的有效影像更完整地保留，背景和摆正也可接受”，不能用框面积变大、平均坐标误差下降或训练完成替代。
