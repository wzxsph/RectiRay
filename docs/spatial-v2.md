## 协议

1. A：使用完整 5258 个开发视图，对照旧动作规则与预测网格规则；完美输入
   与冻结模型真实预测分开报告，不以理想输入成绩冒充模型成绩。
2. B：32 张训练原片按原始长宽比排序等距选择，每张生成 4 个固定场景，
   共 128 视图。比较 GAP-H8、GAP-直接四角、空间-直接四角、空间-热图积分。
   相同 G0 编码器初始化，冻结编码器/BN，Adam，头学习率 1e-4，有效 batch16，
   clip1。依次共同检查 500/2000/5000 步；不得只延长有利实验。
3. B 拟合里程碑：平均角点误差≤输入对角线0.5%、逐图平均误差P90≤1%、
   全部128视图四角合法。未满足前不直接投入全量研究；全部失败先排查实现与梯度，
   然后一次匹配 conv5 解冻复验。GT 比例只用于定位诊断，不算端到端成绩。
4. C：全部4114训练原片；478开发、28隔离不混入训练。保持轻形变为主，
   film投影面积≥30%，至少80%拍摄视图>50%；film和screen标签分离。
   比较全局/空间表示，再逐项加入conv5、覆盖及输出几何损失，三配对种子，
   有效batch64，共同保存1250/5000步。224通过后才比较384。
5. 最终报告同时包含定位、成图、动作、原片保护、真实照片和CPU导出。
   90%自动成功与内容/比例/回归等条件共同验收；训练完成不等于候选准入。

完整数字源片画布是目标，包括其原有黑边。输出始终取自原照片，不生成新影像。
未校准的安全余量不能表述成置信区间；越界预测不能钳回边界后冒充成功。
旧 D、旧 T、47张实拍已经暴露；新场景留出不能表述成患者独立外部验证。

## 接口

`ptrn-spatial-corners-v2` 明确返回输入像素中心坐标的四角 `[N,4,2]`，
与旧 H8+δ 九维输出不兼容。几何策略 `ptrn-spatial-policy-v2` 接收照片坐标四角、
比例和来源信息；可靠来源直接保留。比例模型在定位稳定后单独验证。

## 各阶段入口

```bash
# A：输入既有冻结预测与完美答案，分别重放策略。
PYTHONPATH=src python -m ptrn_hip.spatial_policy_audit \
  --prior-run /path/to/unified-v1 --run .local/runs/spatial-v2 --scope all \
  --verify-perfect-regression

# B：四个arm共同依次运行500、2000、5000；每个阶段完成后保存共同决策。
KERAS_BACKEND=torch PYTHONPATH=src python -m ptrn_hip.spatial_runner train-small \
  --run .local/runs/spatial-v2 --prior-run /path/to/unified-v1 \
  --manifest /path/to/manifest.local.json --weights /path/to/b1-1/diagnostic.weights.h5 \
  --g0-checkpoint /path/to/ratio-v1/G0/step-1250.pt \
  --arm spatial_heatmap --target 500 --stage head --microbatch 8

# 一次conv5复验使用spatial_conv5_runner，stage=last_block、microbatch=4；
# 其余参数、四臂与检查点相同，产物独立存入B-conv5-cached。
# 四臂共同检查点齐备后，以CPU验证数据、预测、checkpoint及配置并形成决策：
PYTHONPATH=src python -m ptrn_hip.spatial_protocol summarize-small \
  --run .local/runs/spatial-v2 --folder B --step 500
# C入口为spatial_full_runner；默认仍要求B通过。
# 仅本次用户明确要求的失败B探索使用显式 --allow-failed-b，
# 配置绑定六份B共同决策、24份评估、空pass_arms和原始SHA。
```

本机参数与调度脚本位于`.local/`，源码、数据、初始化、配置与checkpoint均绑定SHA。
CPU测试可运行`CUDA_VISIBLE_DEVICES='' KERAS_BACKEND=torch PYTHONPATH=src python -m pytest -q`。
当前完整源码测试239项通过，编译检查通过。TorchScript弃用和固定尺寸trace警告仍存在；
导出用显式输入契约拒绝尺寸、dtype和非有限输入，并验证N=1/2重载等价。

可选正留边余量会检查实际输出角反投影，防止未经验证的外扩越过捕获区域。
默认零余量的旋转裁剪仍可能在输出矩形角部出现少量黑边：完美D的14个crop存在此现象，
最大原照片角部越界2.95px；这14例总背景最多1.20%，已计入既有5%背景门。
“GT片区完整”不等于“输出完全无黑边”，本轮未新增零黑边门槛。

C的完整性项保留漏片:背景=3:1，另含折叠/短边项，以及显式的真实照片边界项。
边界项使用缓存的逆补边矩阵与照片尺寸，将预测四角映回照片后对越界距离作hinge罚项，
按照片对角线归一化，初始权重5写入配置。它不钳回四角，不从GT底片边界获取照片范围。
这避免“仍在224画布内、却已经落入补边”的越界漏罚；该候选损失已做梯度和边界单测，
尚未训练验证，不是几何合法性的硬保证，也不能追溯改变B的结论。

原停止判定建议先在同一128视图验证真实照片边界项与完整性目标；
2026-09-23 的用户新指令改为先启动全量探索。尚无可供应用自动替换的完整取图模型。
