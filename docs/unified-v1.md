# PTRN 统一几何头实验

本轮已完成固定预算训练及全部既定评估，没有可替换应用的合格结果。B1.1 继续作为现有应用基线。结果以本地 run 的准入记录为准，不能将训练完成等同于验收通过。

网络为 DenseNet201 → 1920 维全局特征 → 一个 Dense9，预测 H8 与 log 比例残差 δ。四角定位、比例估计共同用于从原照片取出最终工作图；没有独立动作分类头。原片可信来源直接保留，未知来源按几何容差选择保持、裁剪旋转、透视或待确认。不会生成新的影像内容。

训练损失为四角 SmoothL1 加 0.25 倍 log 比例 SmoothL1。当前预测四角的边长比例作为残差基线，只对这条比例梯度停止反传；四角 8 个输出仍接受定位监督。G0 的 H8 参数完整复制，δ 零初始化。

输入 224 或 384，等比例补边；像素中心归一化使用 `size-1`。公开导出契约为 `ptrn-unified-geometry-v1`，NHWC RGB float32 0–255，输出最后一维是 δ，不能按历史九维模型的完整 log 比例解码。

全部 4620 张底片先按冻结清单核对：4114 训练、478 开发、28 重复隔离。80000 个训练场景槽位覆盖每张训练原片 19 或 20 次，全部都有保留类和拍摄类；固定配方为 8000 数字原片、4000 噪声原片、4000 GT 正确展平图、64000 拍摄图。拍摄图正面/轻微/中等/较大为 45/35/15/5%，真实片区占整幅照片至少 30%，80% 超过 50%。倾斜与占幅不兼容时仅在原档内重新采样相机姿态，不拉伸或丢弃原片。

训练固定四组共 560000 次曝光：S224 冻结编码器，训练完整头 5000×64；从同一 S 检查点分别启动 F224（只训头）、J224（头和最后编码块）、J384（同 J224，独立从原图补边），各 1250×64，重置优化器。BatchNorm 全程冻结。头学习率 1e-4，编码器 1e-5，梯度裁剪 1。联合组使用 BF16 前向及 FP32 损失；单头组使用 FP32 特征。

硬盘空间有限，因此保存固定场景清单和随机种子，缓存约 0.61 GB 的 1920 维 FP32 编码特征；不落盘完整 80000 张照片。联合训练从同一原片和槽位重新渲染，384 不放大 224 缓存。缓存、检查点均绑定源代码快照、G0、清单和输入契约；恢复时核对签名与完成日志。所有影像、源索引、逐例结果、权重与运行日志仅存于 Git 忽略的 `.local/`。

D 为 478×11=5258 张固定开发场景，参与选权重和九组几何阈值校准。T 为相同 478 张底片的新封存场景，共 4780 张；候选与阈值冻结后才渲染。T 不是独立患者测试。另执行历史 R 的 1434 清晰＋1434 噪声固定回归，以及 47 张已暴露、无配对真值的真实照片观察，不能据其报告真实比例准确率。

几何评估从 GT 相机投影和原片实际尺寸计算 9×9 网格，检查最终输出的比例、漏片、残留背景与方向；不使用分别按宽高缩放到正方形的评估，以免掩盖拉伸。所有失败和待确认均留在自动成功率分母。合成质量、真实观察、导出一致性和 CPU 延迟全部通过后才允许本地应用接入。

## 本地执行

本次源码冻结版本的自动收尾在 GPU 可见环境中跟踪导出时，会把 CUDA 操作固化进计算图，导致 CPU 导出校验失败。实际恢复将 `freeze_selection(args, calibrate_development(args))` 单独放在 `CUDA_VISIBLE_DEVICES=''` 的子进程中，完成真正 CPU 导出、差分校验、CPU 基准和锁定；随后恢复原 GPU 环境执行 `finalize`、`audit-after`，最后仅刷新 `final_report`。不要复用失败的 CUDA 跟踪文件，也不要将整个 `finalize` 隐藏 GPU：T/R 默认使用 CUDA。失败产物保留，训练源码和权重未改变；未来完善启动器应在新的源码版本中执行。

在仓库根目录，使用具备 Keras 3/PyTorch 后端和 CUDA 的现有 Python 环境。以下路径为占位，替换为本地授权路径；不得将原始清单或影像放入普通 Git。

```bash
export KERAS_BACKEND=torch
export PYTHONPATH=src
python -m ptrn_hip.unified_runner prepare \
  --manifest /path/to/manifest.local.json \
  --prior-run /path/to/ratio-v1 \
  --run .local/runs/unified-v1 \
  --weights /path/to/b1-1/diagnostic.weights.h5 \
  --g0-checkpoint /path/to/ratio-v1/G0/step-1250.pt
```

使用同组参数运行 `preview`，本地检查各几何档及极端原片尺寸示例，然后执行 `run-all`，另加 `--real-dir /path/to/authorized-phone-photos`。主控依次启动独立进程，执行缓存、100-step 预检、四组训练、冻结后的评估与原片完整性复核。运行期间不改训练源或配方，不自动延长预算。崩溃后使用同命令恢复，配置或源码变化会拒绝继续。

`status.json` 为当前阶段；组内 `history.jsonl` 记录每步损失、曝光、显存及用时；`step-*.pt` 配套 SHA 侧车；`source-inventory.json` 与源码快照绑定未提交实现，不将 Git 基线 SHA 冒充新增源码提交。`failure.json` 保存中断原因，不能忽略后宣称完成。
