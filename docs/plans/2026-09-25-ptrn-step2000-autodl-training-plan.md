# PTRN 从 2000 步出发的 AutoDL 训练计划

> 本文保留 2026-09-25 至 26 日的方案和启动期快照；不维护后续训练终态、最终选权重或应用准入。当前研究定位和复现入口见[仓库 README](../../README.md)与[复现指南](../reproducibility.md)，终态以受控运行目录的完成标记及检查点绑定为准。

## 目标与决策边界

本计划接续[实拍过裁讨论稿](../2026-09-25-overcrop-discussion.md)，目标是在保留现版背景处理收益的同时，减轻实拍照片上过小的预测框：从原照片中尽量完整取出**实际拍到的** X 光影像，去掉背景并摆正；缺边缺角时只展平已拍到的部分，不补画缺失医学内容。训练地点为 AutoDL RTX 4090 D；训练已启动，应用模型尚未替换。

本轮保持 DenseNet201、现有空间解码器、四角＋比例输出与取图函数不变。从正式训练的 **step 2000** 建立**一条统一的新训练路线**：同一个新数据版本同时降低缺损频率与程度、补足近满幅拍摄图、加入轻微自然边界过渡。1250、2000、5000 的旧结果只用于前后比较。背景家族继续使用 40% 查看器、25% COCO、25% 同色、10% 混色，保留已有背景改良。屏幕／实体胶片与拍摄干扰独立采样；新的外观配方已通过合成夹具及服务器真实场景抽样校验，以下为启动时的执行记录。

启动期快照（2026-09-26）：首次分支在 +250 保存权重、+270 因 CUDA Graph 与固定页内存线程并发中断；审计迁移至新运行目录后从 +250 继续，无重复优化步。训练中使用 eager 诊断，训练输入线程退出后再做独占 CUDA Graph 的严格完整开发集评估。快照时 +250 诊断 512/512 已完成，+500 检查点已保存并进入诊断。原因、权重 SHA 和恢复记录见[AutoDL 训练实践记录](../autodl-training-practice.md)。这不是完成或实拍验收结论。

这里的实拍百分比比较的是**两个预测区域的面积**，并非真实医学影像被切掉的比例；47 张尚无可靠完整边界标注，不能据此判定实际裁损率。降低缺损是本轮明确的数据设计选择，并非已经证实的单一病因。由于三个数据改动一起训练，本轮结果也不能单独归因于其中某项。此前 100 张合成网页与 47 张实拍均已参与开发，不属于独立测试。

数据依据：`src/ptrn_hip/partial_data.py`、`partial_synthesis.py`、两份完整开发评估 `evaluation-{1250,5000}.json`、本地 `stage-review/real47/report.local.json`。2000 步没有现成的完整 5736 张开发评估；在正式对照前补跑并明确标记为已暴露开发集。

## 数据版本与合成配方

建立新的数据／渲染版本及独立缓存命名空间，旧冻结开发场景、旧检查点与旧比较网页原样保留。仍以 4114 张训练母片训练，478 张母片形成固定的 5736 视图开发集，28 张隔离母片不参与调参。母片、背景、场景种子、几何、缺损、材质和拍摄外观分别有种子及 SHA；强度、实际占幅、可见率、预／后裁类型逐张审计。新合成应先制作小批审阅图，对比背景真实性、边界过渡及 224 输入是否仍保留信息。

**占幅方案。** 占幅是照片内可见底片面积占照片总面积，不是目标宽度比例。保留全体样本约 20% 的逐像素原片；其余拍摄图采用统一配方：近满幅 90%–<100% 占 20%，75%–90% 占 30%，50%–75% 占 35%，30%–50% 占 10%，10%–30% 占 5%。这使 85% 拍摄图占幅 >50%，只少量加入远景。近满幅拍摄图要同时包含反光、摩尔纹等外观，不能全部以原片旁路替代。强透视／大角度和高占幅若几何上不相容，预先设条件分布并审计，不能通过非等比拉伸或重试时暗中降档实现。

**缺损方案。** 拍摄图不缺损 80%，后裁缺 1%–3% 为 12%，缺 >3%–8% 为 6%，缺 >8%–15% 为 2%。相较旧配方，不缺损由约 60% 提到 80%，最重的常规后裁由缺 12%–28% 降到最多 15%；超过 15% 的缺损保留在压力验证和审阅中。仍覆盖单边、缺角和相邻两边；可见部分必须完整保留，虚拟四角不可被裁回照片边界。母片预裁剪降到拍摄图的 10%–15%，每张裁去源面积不超过 5%–10%，避免与明显后裁叠加。该分布是本轮统一训练的**初始配方**，合成审计若显示某档难以实现，应先修正生成方法并记录差异，不能暗中换比例。

**边界过渡方案。** 在现有同色／混色背景上新增受控样本：近色边框、低对比背景、局部光照渐变、边缘轻失焦，以及原片边缘与背景之间宽度很窄的自然混合。以照片尺度和最终 224 输入尺度同时定义过渡宽度，首批拟比较约 0.5–2 个 224 输入像素的轻柔边界与少量 2–3 像素难例；范围须先经过样例审阅。屏幕表面反射、胶片观片灯反射及整图镜头模糊各自有作用区域。内部影像保持原始像素，不给骨骼结构补画纹理；同色程度、边缘宽度和失焦强度逐张记录。边界几何真值仍是合成底片外边界；若视觉上已不可辨，单列为不确定层，不把“模型猜中生成器内部坐标”当作真实可用的证明。离线评估分别报告清晰／轻过渡／极低对比三层。

外观预览 `ptrn-capture-appearance-v1` 目前只是独立审阅产物，未进入旧正式训练。加入新版本前先核对屏幕纹理及反射在 COCO、同色、混色分支确实改变原尺度和 224 输入；强干扰难例保留，不靠删样本提成绩。原片、训练源与医生数据不改写。

## 从 step 2000 统一训练

正式检查点 `step-2000.pt` 已在本地，SHA256 为 `016cfc5b3fb97699eb38b6ce8850c7d4802797602d8fba04f233959744120535`，包含模型、Adam、步数、样本游标和随机数状态。变更数据或渲染源码会改变绑定，旧严格恢复入口因此会拒绝直接续训。实施时建立**一条新的、显式记录来源的训练 run**：加载 step 2000 模型与 Adam，从新数据游标 `branch_step=0` 开始；记录父检查点 SHA、旧／新绑定、配方和新随机状态。这是以 2000 步为起点的新配方训练，不能把新游标冒充旧数据的精确续训。启动前核对零步模型与优化器逐张量一致，并验证新 run 的断点恢复能正确还原样本游标和 RNG。

统一配方一次性纳入上述占幅、缺损和自然边界改动，保留背景处理。训练保持现有损失（坐标＋可见区域漏片／背景＋几何＋辅助掩码＋比例）、BN 状态、输入 224、有效 batch 64。现有损失已含漏片项，本轮先用数据修正验证效果；若仍过裁，再另行研究目标权重或编码器。2000 步已有内缩，1250 步仍是实拍完整性参照。

使用一个固定母片顺序、场景种子表及背景清单，几何、缺损、介质和外观从彼此独立的随机流生成，保证失败重试不会悄悄改变其他档位。记录每张实际占幅、缺损和边缘强度的联合分布。不得通过拒绝困难图、静默重抽或改变验收集合来抬高取图率。

预定在新 run 中训练 **3000 个新增更新步**，每 250 步保存检查点，至少在 +250、+500、+1000、+1500、+2000、+2500、+3000 检查进展，最终按完整取图表现选权重，不默认最后一步最好。+500、+1000、+1500、+2000、+2500、+3000 的权重可在服务器训练继续时异步下载到本地，用固定 47 张实拍作同设置预览；实拍照片仍留本机。短程检查用于发现数据或训练故障，不按单个波动频繁重启。同一 run 跑满预定预算，除非出现非有限损失、绑定错误、持续供数故障或已明确的明显裁损回归。新增步数在记录中写作 `branch_step`，不与旧正式 run 的同名绝对步数混称。总 GPU 时长与存储先由下一节实测决定，不把 0.314 秒/步的短程热缓存测速写成整轮 ETA。

## AutoDL 资源与持续吞吐

### 以完成时间而非显存占用优化

执行时重新读取 AutoDL 的 GPU、CPU cgroup 配额、内存和数据盘余量；旧实例为 4090 D 24 GiB、16 核 CPU 配额、约 60 GiB RAM。旧正式训练的三段实测为 0.463、0.496、0.474 秒/步（约 138、129、135 张/秒）。旧热缓存 80 步短测为 0.314 秒/步（约 204 张/秒）；其 `loader_wait_seconds=0.0021%` 仅计 Python future 等待，**没有计入 GPU 等待传输事件，也没有计入每步验证、检查点和工作进程重启**，不能当作整轮利用率或 ETA。旧缓存落盘生成 1024 张需约 18 秒（约 57 张/秒）；旧常驻 CPU 在线合成加训练 1024 张约 10 秒。这是不同路径，不能把 57 和 204 直接相减后断言 CPU 合成本身必然不够快；逐张压缩、全局锁与 `fsync` 可能才是瓶颈。

本轮 3000×64＝**192000 张次**。224 RGB 本身未压缩约 26.9 GiB；按当前训练输入连同两张 float32 掩码约 0.526 MiB/张估算，整轮约 99 GiB，远超现有 8 GiB 训练缓存，必须有滚动生产或经实测证明可行的压缩缓存。旧热缓存步时乘 3000 约 15.7 分钟，旧正式步时乘 3000 约 23.5 分钟，二者都**不是**新训练预估耗时，因为没有包含新配方供数、开发评估和保存。优化目标为从准备第一个场景到最后一个完整评估完成的墙钟时间；同时分别报告 GPU 付费时间、纯训练时间、供数等待、验证预测、CPU 指标和检查点耗时。

### 启卡前准备与候选供数路径

先冻结 192000 个训练样本的母片 ID、背景 ID、场景种子和消费顺序，生成轻量清单；照片像素和标签按需提前合成，绝不把相同母片的不同轮次误认成一条缓存。固定 5736 张开发场景与训练清单分别绑定版本和 SHA。若无卡实例的 CPU／数据盘仍可用，先在无卡阶段完成清单、参考开发集缓存、样例和首批训练分片，减少 GPU 付费等待；若该实例无卡时不能运行，则启卡后并行准备训练首批与固定开发集。一旦训练队列达到经测速确定的起步水位，就先开始训练，不等待全套开发输入；父 step 2000 基线只读评估可以在训练结束后补做，不能为了它让 GPU 空等。现有入口会**同步**建立整套开发输入库后才训练；旧冷开发缓存曾耗时 242.5 秒，实施时改成分片后台准备与顺序消费，不能保留这个启动屏障。

对同一新配方、同一批样本、同一 batch 64 做三种**供数实现**的配对测速；这不是三组模型训练实验，最终仍只有一条统一模型训练 run。CPU 在线与 CPU 缓存须逐像素、逐标签一致；GPU 渲染若有插值差异，先作为独立渲染版本核对像素容差、边界及标签，再冻结为该统一 run 的唯一版本，不能在训练中途换渲染口径。旧固定开发集仍用原参考渲染。

| 路径 | 实施内容 | 必须计入的成本 |
| --- | --- | --- |
| 常驻 CPU 在线供数 | 多进程提前合成到有界 RAM 环形队列，训练直接读取；可复现样本按 ID 重建 | 解码、合成、掩码与标签、内存复制、训练及验证时竞争 CPU |
| CPU 无损滚动缓存 | 场景提前合成，按 256–1024 张分片批量压缩／原子提交；RAM 队列从盘预取 | 生成、压缩、锁、同步写、读盘、解压、训练及缓存淘汰 |
| GPU 批量预生成 | GPU 空档或明确预生成时段合成，异步回传，由 CPU 写入同一无损分片格式 | GPU 合成占用、传输、写盘、读盘、训练被延后的时间 |

每条路径先用 step 2000 检查点的临时副本跑 1024／4096 张短测，不把测速权重作为新模型；再按测得的每张缓存字节数 `b` 计算训练缓存容量 `N=floor(8 GiB/b)`。选定路径的长测至少跨**两次缓存轮转**，或覆盖 500 个连续真实更新步，取更严格者；长测包含开发预测和 CPU 指标活动的一段，并记录冷缓存与热缓存。短测各做至少三次同序配对测速。确认供数正确与版本冻结后，正式 run 的前段就用来验证长程供数；达不到门槛时从已保存的同一 run 状态修复并继续，不另开模型训练组。选择完整链路墙钟最短、长期供数稳定的路径，不因为 GPU 合成“看起来更忙”而启用它。旧 `torch-photo-v1` 的 1024 张完整链路约 32–36 秒，慢于旧 CPU 在线路径约 10 秒；新外观配方必须重测，不能沿用旧结论。

缓存写入优先消除现有每图 ZIP 压缩、全局 `.quota.lock`、SQLite `synchronous=FULL` 与单图 `fsync` 热点；使用分片临时文件、校验、原子改名与一次索引提交。保留 RGB `uint8`、float32 标签和掩码原精度，不能用 JPEG 或标签量化换速度。损坏分片按原 ID／种子重建；缓存拒写、缺片、重建次数必须显式计数，不能静默退回重复在线合成。缓存提交完成顺序可以乱，训练读取严格按预定 ID 顺序；恢复后下一个样本 ID、种子、优化器与 RNG 必须一致。

### 有界队列、CPU 配额与 GPU 连续计算

CPU 总预算始终由 16 核 cgroup **共同**约束：主训练／PyTorch 最多 4 线程，普通时 12 个单线程生产者；开发缓存准备或 CPU 指标活跃时改为主进程 4＋训练生产 8＋开发准备 **或** 指标 4。写盘进程计入生产者名额；不可再叠加一套 12 进程预填池。OpenCV、BLAS 与每个工作进程的隐式线程设为 1，并监测 cgroup 限流；CPU 核数占满但 GPU 等数据时，优先调合成／压缩的分工，不机械加进程。固定开发输入在第一次使用前逐片准备；开发准备完成后，将其 4 核名额还给生产或指标。

训练用两个有界队列：生成任务按样本 ID 排序，完成后的 RAM 图像按 ID 交付；磁盘滚动缓存是可重建的二级层。启动低水位暂定 4096 张、高水位暂定 8192–16384 张，**最终容量按实测图像字节数、RAM 和供需速度定**，不能因为预填太久而让 GPU 空等。RAM 开发输入库上限 8 GiB、固定页缓冲上限 1 GiB、全进程内存压力线 48 GiB；训练滚动磁盘缓存先守 8 GiB、开发缓存 12 GiB、总计 20 GiB 且至少留 15 GiB 空盘。若实测空间允许调整，先计算源数据、检查点及失败恢复余量，绝不清理非可重建产物。队列满则生产者背压；队列低于低水位时优先供给即将消费的 ID。提前量以 `Q/(C−P)` 估算（`Q` 为待用张数、`C` 为消费张/秒、`P` 为同时生产张/秒，且仅在 `C>P` 时成立）；**稳定阶段必须使供给跟得上消费**，否则扩大预填只会推迟耗尽。目标是生产速率达到同期消费速率的至少 1.1 倍，并保证开发指标占用 4 核时队列仍可覆盖该阶段的实际缺口。

GPU 仅由一个调度入口持有，先保持有效 batch 64、已验证的精度模式、固定页内存、独立 H2D 流、双缓冲与 CUDA 事件；下一批传输与当前批计算重叠，并验证缓冲复用前事件已完成。现有每 4 步回收是起点；旧 GC8 虽更快，但末 100 步显存增长曾超过 128 MiB 约束，不能直接换用。用新配方复测 GC1／4／8、等效 batch 64 下的物理 microbatch 32／64 及显存峰值，只有输入次序、有效 batch、数值检查和显存增长约束都保留时才改；不为了占满 24 GiB 显存而改变优化轨迹。模型训练峰值目标低于 22 GiB，留给验证与异常波动。若训练 CUDA 时间已占大头，GPU 生成可能拖慢整轮，优先 CPU 前置生产；若 CPU 或写盘长期跟不上，再比较 GPU 预生成是否净节省总时间。

每 250 步的检查点当前会同步序列化并原子替换。先单列保存造成的 GPU 等待；若它在完整 run 中占比明显，再把模型与 Adam 状态复制成**不可变快照**，交给至多一个后台写盘任务，完成原子落盘、SHA 与读取复验后才声明检查点有效。队列满则等待有效检查点，不丢保存节点；若安全快照成本不低于原同步方式，继续使用同步保存。DataLoader／工作池保持常驻，不因一次验证或保存反复启动。

### 训练期间完成验证，而不积压评估

唯一通过旧数值容差的完整开发预测方式是 batch 1 CUDA Graph；现有 batch 8／16／32 没有通过一致性检查，不能为吞吐擅自扩大。一个 GPU 所有者在**每次训练更新之间**插入若干次 batch 1 预测，预测立刻按检查点 SHA／样本 ID 分片落盘；CPU 指标池拿到分片就计算漏片、背景、网格与比例，GPU 继续下一次更新。预测和指标各有进度、完成状态与故障，CPU 指标慢不阻塞下一次训练更新，但待汇总任务有上限，不能无限排队。训练中至多一个完整开发集预测任务；完成 5736 个唯一 ID 且全部指标齐全才标记完整评估。

具体排程为：旧 step 2000 基线完整评估（可在训练后补做，但须用相同固定开发集）；新分支 +250、+500 使用预先固定的 512 张分层诊断集，分别在下一节点前完成预测，+250 后到 +500 的 250 个更新至少需 `ceil(512/250)=3` 张／更新；固定开发输入最迟在 +800 前准备齐全，**+1000 启动一次完整 5736 张评估，目标在 +2500 前完成 GPU 预测**；+1500、+2000 保存权重并查看训练／本地 47 张实拍趋势，不再排第二个完整任务；+2500 可在前次预测已完成后跑固定诊断集；+3000 停止更新后完整评估最终权重，并按结果补评其他候选检查点。旧代码每更新只预测 2 张，需要 2868 个更新才跑完一次；从 +1000 到 +2500 只有 1500 个更新，所以起始配额至少为 `ceil(5736/1500)=4` 张／更新，且是 4 次 batch 1 预测。每 100 步重算 `ceil(剩余未预测张数/截止前剩余更新步数)`，用实际每张 GPU 毫秒及每步额外耗时给配额设上限。如果开发输入未能在 +800 前就绪，训练照常前进，记录准备瓶颈，并改为 +1500 启动、+3000 前完成预测的明确后备时段；若 +1500 仍未就绪，则把该次完整评估显式列为延迟任务，在训练后完成并计入总耗时。若配额会显著拉长总墙钟，则报告原因，在同一 GPU 所有者下用短的连续预测时段完成剩余量；此时训练更新暂缓，但 GPU 始终在做有效计算，CPU 指标仍同步推进。不得悄悄把未完成的 +1000 评估挂到 +3000 之后再声称它已完成。

### 观测、调整与停止门槛

服务器轻量采样每 10 秒记录 GPU 活跃／空档、显存峰值、CPU `cpu.stat` 限流、内存、磁盘空量与读写吞吐；每 100 个更新记录训练步墙钟 P50／P95／P99、CUDA 计算、H2D 事件等待、Python 取数等待、验证预测占用、生产／消费张/秒、队列深度及最旧待用 ID、缓存命中／拒写／重建、检查点保存和工作进程重启时间。训练主计时从取下一批开始到验证插入、检查点及状态落盘结束；`train_step` 内计时另列，避免把验证和保存藏掉。监控只读告警，不自动改模型或门槛。

连续三个 100 步窗口取数或 H2D 等待超过对应墙钟的 5%、队列持续下降且供给小于消费、或 GPU 出现无任务的长空档，就先根据分段计时定位解码／合成、压缩写盘、传输或验证调度，再在**相同样本顺序**下修复；不能靠丢难例、降低图像质量或仅拉大队列掩盖。接近 48 GiB 内存、22 GiB GPU 峰值或 15 GiB 空盘时背压并保存安全状态；源绑定不符、非有限训练值、损坏检查点立即停止。评估指标失败只标记该检查点评估失败，健康训练可继续，但最终验收必须补齐。性能报告同时给出冷／热缓存、训练加完整评估总耗时、GPU 付费耗时，以及最慢阶段的实际原因；若稳定供数、完整评估或等价性未过，就不宣布“服务器利用率已优化”。
